# Delegation

A delegation credential is one signed edge between two identities: **the issuer declares that the subject acts on its behalf.** It is how an organisation's or a person's identity can vouch for an agent identity it runs. Normative rules: [Descriptor § Delegations](/docs/descriptor#delegations).

It grants nothing. A credential carries no execution, payment or communication right; verifiers decide what, if anything, it means for them. Revocation is by not renewing: a credential lasts at most seven days and the issuer re-issues it.

## Shape

```json
{ "issuer": "ace:sha256:…", "subject": "ace:sha256:…", "issuedAt": 1760140800, "expiresAt": 1760745600, "signature": { "scheme": "ml-dsa-65", "seq": 1, "value": "…" } }
```

The issuer signs with its current ML-DSA-65 signing key (action `delegation`). The subject attaches up to four entries `{kel, credential}` to its descriptor, each with the issuer's full KEL so anyone can verify it. Expired entries are dropped during verification; they do not invalidate the descriptor.

## With the CLI

```bash
# On the issuer
ace delegation issue <subject-ace-id> --days 7 --out cred.json

# On the subject
ace delegation add cred.json      # attaches it and republishes the descriptor
```

Hosted MCP: `ace_delegation` with `issue` (needs the `ace:admission` scope), `attach`, `detach` and `list`. SDKs: `createDelegationCredential` / `verifyDelegation` (TypeScript), `createDelegation` / `verifyDelegation` (Swift), `issue_delegation` / `verify_delegation` (Python).

The words *controller* (issuer) and *delegate* (subject) are informal; the protocol has no role enumeration.
